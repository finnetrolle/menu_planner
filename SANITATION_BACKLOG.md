# Sanitation Backlog

Технический backlog по санации Menu Planner.

Цель: убрать архитектурные слабые места, стабилизировать работу приложения и подготовить кодовую базу к безопасному развитию.

## Правила выполнения

- Идём сверху вниз по очередям.
- Не начинаем следующую очередь, пока не закрыты блокирующие задачи текущей.
- После каждой завершённой задачи прогоняем минимум:
  - `npm run build`
  - `cd src-tauri && cargo check`
  - `cd src-tauri && cargo test`
- Для всех изменений схемы БД синхронно обновляем:
  - `src-tauri/src/database.rs`
  - `src-tauri/migrations/`
  - тесты

## Приоритеты

- `P0` блокирует надёжность данных и релизную стабильность
- `P1` блокирует корректность бизнес-логики
- `P2` улучшает UX, сопровождаемость и архитектурную чистоту

## Definition of Done

- БД хранится в корректной runtime-директории.
- Foreign keys реально включены.
- Схема обновляется контролируемо.
- Операции с блюдами атомарны.
- Один и тот же ингредиент нельзя сохранить в блюде дважды без явного правила merge.
- План питания считается в одном месте и одинаково для всех UI-сценариев.
- Формы не закрываются при неуспешном сохранении.
- Ошибки читаемы для пользователя.
- `DashboardPage` либо реальная, либо убрана.
- Неиспользуемые Tauri-capabilities удалены.
- `npm run build`, `cargo check`, `cargo test`, `npm run tauri-build` проходят после завершения санации.
